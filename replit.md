# Abridge ROI Studio

## Overview
Abridge ROI Studio is a client-side single-page web application designed to calculate the return on investment (ROI) for implementing Abridge in various healthcare settings. It enables users to select a care setting, choose ROI levers, input practice-specific assumptions, and receive real-time financial impact calculations. The application provides comprehensive ROI modeling, including specialized flows for prospects switching from other ambient AI solutions or human scribes, and performance analysis for existing Abridge customers. Its core purpose is to provide defensible ROI estimates for Abridge's AI documentation tool, supporting Abridge's business vision for market penetration and customer value demonstration.

## User Preferences
Preferred communication style: Simple, everyday language.

## System Architecture
The application supports distinct user journeys: an "Explore Path" for new prospects, an "Assess Path" for evaluating current documentation approaches (ambient AI, human scribes, or nursing), an "Expand Path" for existing Abridge customers, and a "Measure Path" for partners to build a value story from deployment data.

### UI/UX Decisions
The application adheres to Material Design principles, utilizing Inter and JetBrains Mono fonts, Abridge's brand color palette (Abridge Cadmium Red #EA2C00), and full mobile responsiveness. Premium UX enhancements include smooth page transitions with framer-motion, staggered entrance animations, input debouncing, and sticky right panels for contextual calculations.

### Technical Implementations
-   **Frontend Framework**: React 18 with TypeScript.
-   **Build Tool**: Vite.
-   **Styling**: Tailwind CSS, custom design tokens, and shadcn/ui built on Radix UI primitives.
-   **State Management**: Primarily React's `useState` hooks.
-   **Data Management**: TanStack React Query for future API integrations.
-   **Security & Privacy**: Client-side processing, automatic session clearing, input security, content security policy, data sanitization, privacy-preserving analytics, and a clear data button.
-   **Deep Linking**: Supports direct navigation to methodology pages and pre-selection of care settings for the Explore flow.

### Feature Specifications
-   **Measure Path**: A 5-page partner report flow (`Your Data`, `What Changed`, `The Value`, `The Opportunity Ahead`, `Your Story`) allowing partners to configure, visualize, and expand Abridge's value based on deployment data. Includes editable targets for expansion and PDF export.
-   **Assess Path — Ambient AI Assessment**: A 5-screen premium narrative flow (`Baseline`, `Domains`, `Score`, `Gap Analysis`, `Summary`) designed to assess ambient AI documentation maturity across Capacity, Revenue, Workforce, and Risk domains. Features dynamic scoring, gap analysis, 3-year projections, and PDF export.
-   **Assess Path — Nursing Edition**: A 6-screen priority-driven strategic alignment tool for nursing leadership. Flow: `Your Nursing Program` (staffed beds, nurse FTEs, bed occupancy) → `What Is Your Nursing Program Focused On?` (6 priority cards: Nurse Retention, Staffing Costs, Nurse Wellbeing, Bedside Presence, Documentation Quality, Future Readiness) → `Exploring Each Priority` (per-priority data collection with conditional inputs: turnover rate/cost, OT frequency + minutes, agency spend, wellbeing surveys, documentation hours, quality concerns, strategic initiatives + real-time sidebar impact calculations) → `Your Strategic Picture` (summary cards per priority with situation + documentation burden connection) → `How to Think About the Investment Case` (narrative framing — mentions "documentation technology" not "Abridge", evaluation criteria, honest tone) → `What Comes Next` (export + schedule conversation). Persistent dark sidebar updates progressively across screens. PDF export: 4 pages (cover, priorities/data, strategic picture, recommended focus + next steps). Files in `client/src/pages/switch/nursing/`.
-   **Learn Methodology Section**: A restructured section providing modular methodology pages for each care setting with a consistent 5-section structure (Context, Value Mechanisms, Assumptions, Honest Limits, Validation Path) and interactive elements.
-   **Multi-Setting Proforma Builder**: Lets users layer multiple care settings (Outpatient, ED, Inpatient, Nursing) into a combined financial model. Flow: Complete Explore for a setting → "Add to Proforma" → ProformaHub (manage settings, inline edit assumptions via expandable panels, add/remove) → ProformaView (stacked area ramp chart, 3-year P&L, card-based pricing/configuration per setting, editable retention phasing, IRR with sensitivity, Quarters/Years toggle). ProformaHub inline editing: pencil icon toggles expandable panel with Y1/Y2/Y3 providers, utilization, cost, and impl fee inputs; "Full Edit" link for driver changes. ProformaView Pricing & Configuration: per-setting cards with Rollout Plan, Pricing, and Annual Investment summary sections (replaces former 10-column table). Features: **Annual IRR calculation** — `buildAnnualIRRCashFlows` aggregates monthly cash flows into annual buckets: Period 0 = implementation fees (if > 0) or Year 1 subscription (if no impl fees), subsequent periods = annual net (gross value minus subscription). `calculateAnnualIRR` returns `IRRResult { annualizedRate, method: "irr"|"mirr", isValid }` — the rate is already annual (no monthly compounding). Newton-Raphson with wider search bounds (up to 50x roughGuess, bisection up to 100x), MIRR fallback for non-conventional flows. IRR is capped at 200%+ for display credibility. **Value-to-Cost** is the primary hero metric (`threeYearValue / threeYearInvestment`, displayed as "Xx" multiplier). Hero bar order: Annual Value | Value-to-Cost | Payback | Simple ROI | Hours Returned. IRR is de-emphasized to a supplementary line under Simple ROI in the metric panels. Two-sided sensitivity analysis uses annual IRR. `hasInvestment` checks impl fees > 0 OR costPerUnit > 0. **PDF "Showing Our Math"**: `buildDriverCalcSteps(snapshot)` reconstructs per-driver formula strings from `fullExploreState` data (timeDriverInputs + docQualityInputs), mirroring ExploreModel.tsx formula logic for all care settings. `getSettingInputSummary(snapshot)` extracts key baseline assumptions per setting. PDF inserts 1-2 "SHOWING OUR MATH" pages after Page 2 (dynamic via `getMathPageCount`) with left-accent-bar pattern per driver (name + value header, calc steps with last step bold + setting color, calibration notes). Page count is dynamic (`BASE_PAGES + mathPages`), all subsequent `PageFooter` calls shift by `mathPages`. Assumptions page enhanced with per-setting driver parameters (realization rates, scenario selections, etc.) via `settingInputSummaries`. **Per-year provider allocation**: `yearlyProviders: { year1, year2, year3 }` replaces linear pilot→full-scale ramp. Users edit Y1/Y2/Y3 provider counts per setting in the pricing table. `getProviderExpansion` uses stepped yearly interpolation (months 1-12 ramp Y1→Y2, months 13-24 ramp Y2→Y3, months 25-36 hold Y3). Driver-specific onset timing (immediate/delayed/phased), Simple ROI metric, utilization ramp via S-curve, conservative retention phasing (0%/50%/100% by default, user-editable), contract term toggle (2-Year/3-Year). P&L table includes "Active Providers" row showing year-end provider counts. Premium narrative PDF export (8 pages: PDFCoverPage + THE THESIS + YOUR CARE SETTINGS + HOW VALUE MATERIALIZES + THE FINANCIAL PROJECTION + THE INVESTMENT CASE + ASSUMPTIONS & METHODOLOGY + HONEST LIMITS & NEXT STEPS) matching the Explore path PDF design system (Manrope font, sectionLabel/calloutBox/cardBg styles, PageFooter pattern, sensitivity IRR panel, honest limitations, disclaimer). PDF also updated to lead with Value-to-Cost and use annual IRR methodology. Chart uses real calendar quarter labels ("Q1 '26", "Q2 '26"...) starting from today's date, with a Quarters/Years view toggle; XAxis interval=1 in quarterly mode for readability. Chart shows value growth trajectory broken out by doc quality (immediate, blue), time savings (3mo delay, red), and retention (phased, green) with gradient fills, go-live markers, time savings onset marker, and payback reference line. Investment line scales with provider expansion. P&L table uses real calendar year column headers (2026, 2027, 2028). Files in `client/src/pages/proforma/` with calculation engine in `client/src/lib/proformaCalculations.ts`. Unit tests in `client/src/__tests__/proformaIRR.test.ts` (53 tests covering monthly IRR, annual IRR, buildAnnualIRRCashFlows, sensitivity ordering, NPV cross-validation, subscription-only IRR, yearly provider allocation, and valueToCost). JourneySelector shows proforma badge when settings are saved.
-   **Driver Onset Timing**: Each proforma driver has an `onset` field: `"immediate"` (doc quality drivers — wRVU, HCC, denials, DRG, CDI, HAPI, Falls — 1-month learning curve), `"delayed"` (time savings drivers — patient access, LWBS, throughput, cost reduction, OT — 3-month operational lag with mini-ramp), or `"phased"` (retention/wellbeing — uses Year 1/2/3 retention phasing sliders). This creates realistic early-month cash flows where documentation value appears first, time savings join after 3 months, and retention builds over years.

### PDF Value Consistency
-   **Single Source of Truth**: All financial values displayed in the Explore PDF export (hero numbers, per-provider values, 3-year projections, at-scale calculations, investment summary) are derived from `sum(drivers array)` rather than from separately calculated `totalValue`/`netAnnualValue` fields. This prevents divergence between the breakdown and headline numbers.
-   **Driver Array Alignment**: The driver array built in `ExploreModel.tsx`'s `handleExportPDF` includes all drivers that contribute to `timeValue + docValue` in `ExploreFlow.tsx`, with matching conditions and formulas per care setting.
-   **Clinician Retention**: A unified `clinicianRetentionValue` calculation serves outpatient, ED, and inpatient settings (nursing uses separate nursing-specific retention). Driver entries are pushed for all three when `calculateRetentionValue` is enabled.
-   **Care-Setting-Specific Exclusions**: Inpatient denials are excluded from the driver array (matching ExploreFlow's exclusion). Cost reduction drivers are included for all non-nursing settings.

### System Design Choices
-   **Calculation Engines**: Two primary engines: one for driver-level calculations and another for narrative flow pillar calculations.
-   **Confidence Haircuts**: Applied at the display layer based on data mode (benchmark, estimated, measured) for transparent ROI presentation.
-   **Consolidated Benchmarks**: A single source of truth for key metrics like utilization, time savings, and denial prevention.
-   **S-curve Adoption Model**: 3-year projections utilize a compounding adoption curve for realistic modeling.
-   **Care Setting Support**: Tailored drivers, defaults, and terminology for Outpatient, Emergency Department, Inpatient, and Nursing settings.
-   **Component-Driven UI**: Utilizes reusable components like `PathwayCard` for progressive disclosure and maintainability.
-   **Configuration-driven**: ROI levers and properties are externally managed for flexibility.
-   **Pure Functions**: Encapsulated ROI calculation logic ensures reliability.
-   **Qualitative Driver Handling**: When users select only qualitative drivers (e.g., Clinician Wellbeing without retention calculation, Rounding Efficiency, HCAHPS, Bedside Time), both the in-app model summary and PDF export show "Qualitative Assessment" or "Not Measured" instead of misleading "$0" values. The `qualitativeDrivers` field in `ExplorePDFData` tracks which drivers are non-dollarized. PDF pages adapt: Page 1 shows "Qualitative Assessment" header, Page 2 lists qualitative drivers with contextual labels, Page 3 shows a qualitative value framework instead of 3-year projections, and Page 4 uses em-dashes instead of zero values.
