MAKE ALL DRIVER ASSUMPTIONS EDITABLE + FIX MATH DISPLAY

## PROBLEM 1: Assumptions aren't editable
Users can see the math but can't adjust it. If they disagree with 
"20% realization" or "$200/visit" they have no recourse.

## PROBLEM 2: Math doesn't add up
The displayed subtotals don't match the total. Fix the calculation logic.

## THE FIX

### EDITABLE INPUT FORMAT

Every assumption in the calculation should be an inline editable field:

INSTEAD OF:
"× 20% time-to-visit conversion"

SHOW:
"× [20]% time-to-visit conversion"
     ↑ This is an input field

Styling for editable values:
- Subtle bottom border or box
- Slightly different background (e.g., #F9FAFB)
- On hover: cursor becomes text cursor
- On focus: border highlights

### BEHAVIOR

1. User clicks on [20] → field becomes editable
2. User types new value (e.g., 15)
3. User clicks away or presses Enter
4. Calculation updates immediately:
   - Subtotal for that section updates
   - Driver total updates
   - Page total updates (in real-time, with smooth animation)

### EDITABLE FIELDS PER DRIVER

PATIENT ACCESS:
- Time-to-visit conversion %: default 20%
- Revenue per visit: default $200

LEVEL OF SERVICE ACCURACY:
- % E/M billable: default 80%
- % under-coded: default 8% (current) vs 12% (Abridge)
- wRVU value: default $45
- wRVU multiplier: default 0.7

DOCUMENTATION-RELATED DENIALS:
- % doc-related denials: default 35%
- Denial cost per claim: default $250
- Prevention rate with Abridge: default 45%

CLINICIAN RETENTION (optional driver):
- Providers at risk: default 2
- Retention improvement: default 50%
- Cost to replace: default $150,000

OVERTIME & LOCUM SAVINGS (optional driver):
- % hours that reduce OT: default 25%
- OT/Locum cost per hour: default $150

HCC CAPTURE (optional driver):
- % Medicare Advantage patients: default 30%
- HCC improvement rate: default 10%
- RAF value per capture: default $1,200
