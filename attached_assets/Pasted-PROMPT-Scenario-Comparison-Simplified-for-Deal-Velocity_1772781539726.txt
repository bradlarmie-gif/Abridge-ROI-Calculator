PROMPT: Scenario Comparison — Simplified for Deal Velocity
Remove the Pricing Sensitivity auto-calculation from the PDF entirely. The default PDF should ONLY show the scenario the user built. No alternative pricing suggestions, no "what if" tables. Clean, focused, one story.
However, if a user wants to compare Per Provider vs Per Encounter pricing, give them a simple way to do it.
1. REMOVE: Auto-Generated Pricing Alternatives
Do NOT auto-calculate or show alternative pricing models anywhere in the PDF. The PDF shows exactly what the user built — nothing more. No "For discussion purposes" table, no "Alternative: Per Encounter" column. This creates confusion and slows the deal.
2. ADD: "Compare Pricing Model" Button on Deal Structure Page
On the Pricing & Configuration section of the Deal Structure page, add a button next to the pricing model toggle (Per Unit/Mo | Annual License | Per Encounter):
Button: "Compare Pricing Models" — small, secondary style (not cadmium red, use outline/ghost button so it doesn't compete with the primary flow)
What it does: Opens a lightweight inline comparison below the pricing section. It takes the user's CURRENT proforma inputs (care settings, providers, rollout, value drivers, everything) and shows side-by-side what the investment and ROI look like under Per Provider vs Per Encounter pricing.
Layout — inline expansion (NOT a modal, NOT a new page):

Key rules:

The LEFT card is always pre-filled with the user's current pricing model and numbers
The RIGHT card is the alternative — user enters the per-encounter price (or per-provider price if they started with per-encounter) and it auto-calculates
Value projections (top line) are IDENTICAL in both cards — only investment changes. Make this crystal clear: "Your value projections stay the same — only the investment structure changes."
ROI, Payback, and Net Value update in real-time as the user types the alternative price
The user clicks "Use Per Provider" or "Use Per Encounter" to select one and it updates the proforma. Or they click Close and keep what they had.
Per Encounter encounters must scale with the rollout plan — fix the current bug where encounters stay flat at 30,000/year across all 3 years. Encounters should auto-populate from: providers for that year × encounters per provider × utilization rate. E.g., Year 1: 75 × 400 × 55% = 16,500. Year 2: 245 × 400 × 75% = 73,500. Year 3: 500 × 400 × 85% = 170,000.
This keeps it simple:
No separate scenario saving
No multi-page comparison views
No extra PDF pages
Just a quick inline tool to gut-check "what does this deal look like at $5/encounter vs $120/mo?"
User picks one, moves on, exports a clean single-scenario PDF


3. FIX: Per Encounter Rollout Plan Auto-Population
Current bug: When switching to Per Encounter pricing, encounters default to a flat number (e.g., 90,000) across all 3 years regardless of provider rollout.
Fix: Auto-populate encounter volumes from the care setting inputs:
Year X encounters = Year X licensed providers × encounters per provider × Year X utilization rate
For the current ED example (50 → 500 physicians, 1,800 encounters/provider):

Year 1: 50 × 1,800 × 55% = 49,500 (after 6-month ramp, roughly half = ~24,750 billable)
Year 2: 260 × 1,800 × 75% = 351,000
Year 3: 500 × 1,800 × 85% = 765,000
These should auto-fill but remain editable if the user wants to override.
For multi-care-setting proformas, show encounters per care setting:
Inpatient: Y1: X | Y2: X | Y3: X
Outpatient: Y1: X | Y2: X | Y3: X
ED: Y1: X | Y2: X | Y3: X
Total: Y1: X | Y2: X | Y3: X
