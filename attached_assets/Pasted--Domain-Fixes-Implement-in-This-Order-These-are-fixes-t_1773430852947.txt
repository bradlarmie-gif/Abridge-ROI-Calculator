# Domain Fixes — Implement in This Order

These are fixes to the four domain screens in the Ambient Assessment (Capacity, Revenue, Workforce, Quality). Do not change the score page, trajectory page, summary page, or overall navigation. Only fix the domain screens.

---

## FIRST: Standardize the working year across the entire application

Every calculation that annualizes time should use the same assumption. Right now the app uses 2,080 hours, 48 weeks, 52 weeks, 230 days, and 250 days in different places. Standardize everything to:

```
CLINICAL_DAYS = 230
CLINICAL_WEEKS = 46
ANNUAL_HOURS = 1,840  (230 × 8)
```

Specific changes:
- Capacity L1/L2: FTE divisor changes from 2,080 to 1,840. Display as "÷ 1,840 (230 clinical days × 8 hrs)"
- Capacity L2: Weekly annualization changes from 48 weeks to 46 weeks
- Capacity L3: 11 clinical months stays (it's consistent with 230 days)
- Workforce L1: After-hours annualization changes from 52 weeks to 46 weeks
- Workforce L2: Formula already uses 230 days — keep it. But fix the PRE-ENTRY benchmark text that currently uses 250 days. Recalculate the benchmark range using 230 days.

Add a note somewhere on the baseline inputs screen: "All calculations use 230 clinical working days per year."

## REVENUE DOMAIN

### Level 1
- Replace every instance of the word "upcoding" with "coding accuracy opportunity" or "appropriate level recapture potential." Search the entire Revenue domain for this word.
- The $1.22M denial exposure and $502K wRVU opportunity appear as headline numbers before the assumptions are shown. Restructure so the assumption text comes FIRST, then the number. Example: "At a 4% national average denial rate (MGMA), documentation-related denial exposure at your encounter volume is approximately $1.22M"
- The HCC $200/member assumption: make this an editable input field. Default stays $200. Label: "Industry estimate for HCC undercapture per VBC member. Adjust to match your organization." Add to the output: "This is a directional benchmark, not your organization's measured HCC data."
- The $100/quality gap assumption: label it at point of use: "$100 per quality measure gap (estimated MIPS/Stars exposure per gap)." Consider making it editable.

### Level 2
- THIS IS THE MOST IMPORTANT FIX. The coding uplift formula is methodologically wrong:
  ```
  Current: 60,000 × $200 × 10% × (30-70% capture) = $360K-$840K
  ```
  This treats coding improvement as a percentage of total encounter revenue. That's not how coding works. A 10% coding specificity improvement means some charts move up a code level — it affects the delta on those specific charts, not 10% of all revenue.

  **Replace with one of these two options:**

  **Option A (recommended): Remove the dollar output at Level 2 entirely.** Level 2 is "Under Investigation" — they haven't measured anything yet. Show only the qualitative signals (the checkboxes for what they're investigating) and frame the output as: "Your revenue cycle is actively investigating. Financial impact will be quantified when before/after measurement is available (Level 3)." This is honest for an investigation-stage level.

  **Option B: Replace with a wRVU-based estimate** matching L3's methodology. Use a conservative estimated wRVU delta (0.03-0.08) instead of the coding percentage approach:
  ```
  [estimatedImpact] = documentedEncounters × 0.05 wRVU × conversionFactor
  ```
  Label as: "Directional estimate using conservative wRVU assumptions. To be confirmed with before/after measurement at Level 3."

- The "30-70% capture" rate: if keeping any dollar formula at L2, this multiplier must be explained. Add: "Capture rate reflects the estimated percentage of coding improvements translating to reimbursement (30% conservative, 70% optimistic)." Better: make it a toggle.
- The 0.5% CDI floor ($152K): move the assumption text to appear before the number, not after.

### Level 3
- No formula changes needed. This is the best calculation in the tool.
- The pre-selection benchmark teaser "$150K-$500K at this encounter volume" needs a source label: "Based on aggregated deployment experience at comparable encounter volumes."

### Level 4
- Sidebar benchmark "$200K-$600K annually" needs a source: "Based on aggregated deployment experience."
- No other changes needed.
