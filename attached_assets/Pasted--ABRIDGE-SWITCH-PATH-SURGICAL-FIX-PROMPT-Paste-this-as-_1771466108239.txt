## FIX 2: CONFIDENCE HAIRCUT — APPLY ONCE, AT THE END

Currently the math is double-conservative: individual engine calculations have conservative assumptions baked in (20% visit conversion, 40% OT conversion, 20% retention realization) AND THEN a confidence haircut is applied on top. This is wrong.

**The fix:**

Each individual engine should calculate at **full modeled value** — no internal realization factors baked in. The confidence haircut (selected on the Uncertainty Calibration screen) is the ONLY conservatism applied, and it's applied once to the final total.

**New confidence haircut values by selection:**
```typescript
const CONFIDENCE_HAIRCUTS = {
  benchmark: 0.55,   // 45% haircut — conservative default
  estimated: 0.70,   // 30% haircut — directional
  measured: 0.85,    // 15% haircut — board-defensible
};
```

Add state for this:
```typescript
const [confidenceMode, setConfidenceMode] = useState<'benchmark' | 'estimated' | 'measured'>('benchmark');
const haircut = CONFIDENCE_HAIRCUTS[confidenceMode];
```

**Apply the haircut only here:**
```typescript
const displayedTotal = Math.round(calculations.totalGap * haircut);
const displayedMonthly = Math.round(calculations.monthlyGap * haircut);
```

Use `displayedTotal` and `displayedMonthly` everywhere values are shown to the user. Use `calculations.totalGap` (raw) only for internal math like the three-year projection base.

**Update the Uncertainty Calibration screen** to set `confidenceMode` when user selects an option. Show the live impact in the right panel: "Modeled: $X → Displayed: $Y after [XX]% confidence adjustment."

Remove these internal realization multipliers from the engine calculations — they are now handled by the global haircut:
- Patient Access: remove the `visitConversion / 100` internal factor → use full hours
- Overtime: remove the `otConversionRate` internal factor → model full hours
- Retention: remove `realizationRate` from the formula → model full replacement cost prevented

## FIX 7: FIX THE THREE-YEAR COMPOUNDING CURVE

Replace the flat three-year projection with a compounding adoption model.

**New projection logic:**
```typescript
// Adoption compounds as utilization deepens
const adoptionCurve = {
  month3:  0.25,   // 25% of full value — ramp up
  month6:  0.55,   // 55% — adoption building
  year1:   0.85,   // 85% — near full first year
  year2:   1.00,   // 100% full value
  year3:   1.08,   // 108% — compounding (more providers, deeper use)
};

// Three-year cumulative (not annual, cumulative):
const year1Cumulative = Math.round(rawTotal * adoptionCurve.year1);
const year2Cumulative = Math.round(year1Cumulative + rawTotal * adoptionCurve.year2);
const year3Cumulative = Math.round(year2Cumulative + rawTotal * adoptionCurve.year3);

// Apply haircut to displayed values:
const displayedYear1 = Math.round(year1Cumulative * haircut);
const displayedYear2 = Math.round(year2Cumulative * haircut);
const displayedYear3 = Math.round(year3Cumulative * haircut);
```

**Cost of waiting calculation (fix this too):**
```typescript
// If they wait 6 months, they miss the first 6 months of ramp
// That value is permanently lost — it doesn't shift, it disappears
const costOfWaiting6Months = Math.round(
  rawTotal * ((adoptionCurve.month3 * 0.25) + (adoptionCurve.month6 * 0.5)) * haircut
);
const costOfWaiting12Months = Math.round(rawTotal * adoptionCurve.year1 * haircut);
```

**Update the chart data** to use the new curve points and show a genuine S-curve shape, not a linear ramp. The chart should visually look like compounding adoption — slow start, acceleration through months 3-12, plateau at year 2-3.
