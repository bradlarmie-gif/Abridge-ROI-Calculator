REPLIT PROMPT:

Redesign the data entry page for the Measure path to handle 
multiple care settings and make the edit/done flow clearer.

═══════════════════════════════════════════════════════════════
PROBLEM 1: CARE SETTING SELECTOR NEEDS TO BE PROMINENT
═══════════════════════════════════════════════════════════════

The care setting dropdown buried in the form is wrong. When 
someone switches from Outpatient to Nursing, the ENTIRE set 
of metrics changes. This needs to be a first-class choice 
that happens BEFORE the form, not inside it.

SOLUTION: Care setting tabs at the top of the form area.

STRUCTURE:

┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  Your Journey with Abridge                                  │
│  Enter your partner's deployment data and metrics.          │
│                                                             │
│  ┌───────────┐ ┌───────────┐ ┌───────────┐ ┌───────────┐   │
│  │Outpatient │ │ Emergency │ │ Inpatient │ │  Nursing  │   │
│  │  ●        │ │           │ │           │ │           │   │
│  └───────────┘ └───────────┘ └───────────┘ └───────────┘   │
│  [tab bar — selected tab has red-orange bottom border       │
│   and red dot, unselected tabs are gray text]               │
│                                                             │
│  ── form content changes based on selected tab ──           │
│                                                             │
└─────────────────────────────────────────────────────────────┘

TAB STYLING:
- Unselected: #999999 text, no border
- Selected: #1A1A1A text, 3px bottom border #EA2C00
- Hover: #666666 text
- Each tab shows a small dot if data has been entered
  (red-orange dot = has data, no dot = empty)
- Tabs sit flush with the form card below

WHEN A TAB IS SELECTED:
- The Partner Profile section stays the same 
  (org name, providers, months, etc.)
- The metrics sections below change completely 
  based on the care setting
- Form state is preserved per tab (switching between 
  tabs doesn't lose data)

PROBLEM 4: FORM SECTIONS SHOULD BE COLLAPSIBLE
═══════════════════════════════════════════════════════════════

When the form is long (especially Nursing with extra fields), 
use collapsible sections so it doesn't feel overwhelming.

STRUCTURE:

┌─────────────────────────────────────────────────────────┐
│                                                         │
│  PARTNER PROFILE                           ✓ Complete   │
│  [always expanded, can't collapse]                      │
│                                                         │
│  [org name, care setting tabs, providers, etc.]         │
│                                                         │
│  ─────────────────────────────────────────────────────  │
│                                                         │
│  TIME & EFFICIENCY                          ∨ Expand    │
│  [collapsed by default after Profile is filled]         │
│                                                         │
│  ─────────────────────────────────────────────────────  │
│                                                         │
│  DOCUMENTATION QUALITY                      ∨ Expand    │
│                                                         │
│  ─────────────────────────────────────────────────────  │
│                                                         │
│  VALUE MODEL                                ∨ Expand    │
│  Pre-filled with defaults                               │
│                                                         │
└─────────────────────────────────────────────────────────┘

SECTION STATES:

Empty: 
- Header: "#999999 text"
- Right side: "∨ Expand" in gray
- No indicator

In Progress:
- Header: "#1A1A1A text"  
- Right side: "∧ Collapse"
- Small orange dot

Complete:
- Header: "#1A1A1A text"
- Right side: "✓ Complete" in #EA2C00
- Can still expand to edit

EXPAND/COLLAPSE:
- Click anywhere on the section header to toggle
- Smooth animation (200ms ease)
- Only one section open at a time (accordion style)
  OR all can be open (your preference — I'd do accordion 
  for mobile, all-open for desktop)

IMPLEMENTATION APPROACH
═══════════════════════════════════════════════════════════════

CODE STRUCTURE:

Create a care setting configuration object:

const CARE_SETTINGS = {
  outpatient: {
    label: "Outpatient",
    deploymentFields: [
      { key: "providers", label: "Providers on Abridge", required: true },
      { key: "totalProviders", label: "Total Providers" },
      { key: "months", label: "Months on Abridge", required: true },
      { key: "encounters", label: "Total Encounters", required: true },
      { key: "utilization", label: "Utilization Rate", suffix: "%", required: true }
    ],
    metricSections: [
      {
        key: "timeEfficiency",
        label: "Time & Efficiency",
        metrics: [
          { key: "timeInNotes", label: "Time in Notes (min)", hasBeforeAfter: true },
          { key: "sameDayClosure", label: "Same-Day Closure (%)", hasBeforeAfter: true },
          { key: "daysToClose", label: "Days to Close", hasBeforeAfter: true },
          { key: "afterHours", label: "After-Hours (hrs/day)", hasBeforeAfter: true }
        ]
      },
      {
        key: "docQuality",
        label: "Documentation Quality",
        metrics: [
          { key: "wrvuPerEncounter", label: "wRVU per Encounter", hasBeforeAfter: true },
          { key: "emLevel", label: "E/M Level", hasBeforeAfter: true, optional: true }
        ]
      }
    ],
    valueModel: [
      { key: "hourlyRate", label: "Provider hourly rate", default: 150, prefix: "$" },
      { key: "visitDuration", label: "Visit duration (min)", default: 30 },
      { key: "revenuePerVisit", label: "Revenue per visit", default: 200, prefix: "$" },
      { key: "wrvuValue", label: "wRVU value", default: 33, prefix: "$" },
      { key: "attributionLow", label: "Attribution low", default: 50, suffix: "%" },
      { key: "attributionHigh", label: "Attribution high", default: 75, suffix: "%" },
      { key: "allocSavings", label: "Operational savings", default: 50, suffix: "%" },
      { key: "allocCapacity", label: "Patient capacity", default: 20, suffix: "%" },
      { key: "allocWellbeing", label: "Provider wellbeing", default: 30, suffix: "%" }
    ]
  },
  
  emergency: {
    label: "Emergency",
    deploymentFields: [...],
    metricSections: [...],
    valueModel: [...]
  },
  
  inpatient: {
    label: "Inpatient",
    deploymentFields: [...],
    metricSections: [...],
    valueModel: [...]
  },
  
  nursing: {
    label: "Nursing",
    deploymentFields: [
      // Different from others — beds instead of providers
      { key: "staffedBeds", label: "Staffed Beds", required: true },
      { key: "nurseFTEs", label: "Nurse FTEs", required: true },
      { key: "occupancy", label: "Bed Occupancy", suffix: "%", required: true },
      { key: "months", label: "Months on Abridge", required: true }
    ],
    metricSections: [...],
    valueModel: [...]
  }
}

This way:
- Adding a new care setting = adding a new config object
- Changing metrics = updating the config
- The form component reads the config and renders dynamically
- No hardcoded field layouts
